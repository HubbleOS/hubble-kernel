---
title: FAT32
---

FAT32 lives in `fs/fat32/`, laid out like ext2:

| File | What it holds |
|------|---------------|
| `fat32_struct.h` | The BPB and directory entry on disk, `FAT32_FS` (a mounted filesystem) and `FAT32_Node` (a file or directory) |
| `fat32.h` | The driver API, the same shape as every disk filesystem's (see the [overview](overview.mdx)) |
| `fat32.c` | The driver |
| `fat32_vfs.c` | The VFS glue, `fat32_init_vfs()` |

The driver's "blocks" are clusters. The whole FAT is read into memory at mount, and `fat32_sync()` writes back only the FAT sectors that changed, to every FAT copy. A `FAT32_Node` remembers where its directory entry is, so a write can update the file size in place. The root directory has no entry of its own (`is_root`).

## Supported

- Lookup, readdir, read, and write (files grow cluster by cluster, holes are zeroed).
- Creating files and directories (a directory gets `.` and `..`), and removing files and empty directories. A full directory grows by one cluster.

## Limitations

- Only 8.3 short names are read and written: names are matched without regard to case and listed in upper case. Long names (LFN entries) are skipped.
- No truncate or rename yet, so `>` on an existing non-empty file fails with `EROFS`.
- 512-byte sectors only.
- No timestamps, and no owners or permissions (`stat` shows defaults).
