The TCP/IP stack is [lwIP](https://savannah.nongnu.org/projects/lwip/) 2.2.1, vendored in `net/lwip/` (the core and IPv4 parts only). `net/` wraps it into what Linux programs expect: interfaces named `ethN` and `lo`, Linux sockets, the `SIOC*` ioctls, rtnetlink and `/proc/net`. Network cards are drivers that hand frames to the stack (see [Network Devices and E1000](e1000.mdx)).

## Layout

| File | Role |
| --- | --- |
| `net/core.c` | Interfaces, the net lock, the net thread, `/proc/net` text |
| `net/socket.c` | `AF_INET` (TCP, UDP, raw), `AF_PACKET` and `AF_NETLINK` sockets as files |
| `net/ifreq.c` | Interface and route ioctls (`ifconfig`, `route`, `udhcpc`) |
| `net/netlink.c` | rtnetlink requests (`ip addr`, `ip link`, `ip route`) |
| `net/port/` | lwIP configuration (`lwipopts.h`) and the platform glue |
| `include/hubble/netdev.h` | The interface between card drivers and the stack |

## How it runs

lwIP runs with `NO_SYS=1`: it has no threads of its own and is not thread safe, so every call into it holds one lock (`net_lock()` / `net_unlock()`, an IRQ-safe spinlock). A kernel thread, started by `net_init()` at boot, takes that lock when a card's interrupt wakes it (`netdev_wake()`), and otherwise every 2 ms (in practice every scheduler tick), to:

- poll each card for received frames (`netdev_ops.poll`, which calls `netdev_rx()`),
- follow link changes (`netdev_ops.link_up`),
- run lwIP's timers (TCP retransmits, ARP, IP reassembly).

Sockets call into lwIP from the syscall that uses them and sleep on a wait queue, with the lock dropped, until a callback from lwIP wakes them. `net_unlock()` also delivers packets queued on `lo`, so loopback traffic does not wait for the thread.

## Interfaces

`lo` (127.0.0.1) is up from boot. Each card becomes `eth0`, `eth1`, ... (up to 8) when it registers; like on Linux it starts down and without an address, and the first one is where traffic for other networks goes.

Configuration is done from userspace, as on Linux. At boot `/etc/init.d/rcS` brings `lo` up and runs `udhcpc` (busybox) on each `ethN`; its script (`/usr/share/udhcpc/default.script`) sets the address, the default route and `/etc/resolv.conf`. By hand:

```sh
ifconfig eth0 10.0.2.15 netmask 255.255.255.0 up
route add default gw 10.0.2.2
echo nameserver 10.0.2.3 > /etc/resolv.conf
```

or with busybox `ip`, which talks rtnetlink (`AF_NETLINK`, `NETLINK_ROUTE`):

```sh
ip addr add 10.0.2.15/24 dev eth0
ip link set eth0 up
ip route add default via 10.0.2.2
```

`ip addr`, `ip link` and `ip route` list interfaces in ifindex order, as Linux does.

lwIP has no routing table: it reaches each interface's own network directly and sends everything else to the default interface's gateway. So `route` and `ip route` can only add or delete the default route; adding a route to an interface's own network succeeds and changes nothing. An interface also has a single IPv4 address: `ip addr add` of a second one replaces the first.

## /proc/net

The files are generated in the Linux formats, which `ifconfig`, `route` and `netstat` parse:

| File | Contents | Generated by |
| --- | --- | --- |
| `dev` | Per-interface packet, byte, drop and error counters | `net_proc_dev()` |
| `route` | The default route and each interface's network | `net_proc_route()` |
| `tcp`, `udp`, `raw` | Sockets and connections, TIME_WAIT included, with their queues | `net_proc_tcp()`, `net_proc_udp()`, `net_proc_raw()` |
| `tcp6`, `udp6`, `raw6` | Only the header (no IPv6) | the same |
| `unix` | Bound AF_UNIX sockets | `unix_proc_net()` |

## In QEMU

`make run` gives the guest an e1000 on QEMU's user-mode network (`QEMU_NIC`: `e1000`, `e1000e` or `none`). The guest gets 10.0.2.15 by DHCP, the host is 10.0.2.2 and DNS is 10.0.2.3; the guest reaches whatever the host reaches. To reach a server in the guest from the host, forward a port with `QEMU_HOSTFWD` (QEMU's hostfwd form, space separated):

```sh
make run QEMU_HOSTFWD="tcp::8080-:80"   # then, in the guest: httpd -p 80
curl http://localhost:8080/
```

`/bin/nettest` (`usr/demos/nettest.c`) checks `select`, `pselect`, `ppoll` and `epoll` over TCP on 127.0.0.1; the same binary passes on Linux.

## Limits

- IPv4 only: no IPv6, so `AF_INET6` sockets fail with `EAFNOSUPPORT` (resolvers fall back to IPv4).
- No DHCP or DNS in the kernel; both are userspace (`udhcpc`, the libc resolver).
- No routing table beyond the default route, no multicast, no firewall.
